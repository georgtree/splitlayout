splitlayout

Command-line help

Argparse-based public commands accept -help, print their descriptions and argument details to stdout, and return without changing the layout. Required arguments and other supplied values are ignored for help. Creation help allocates neither a TclOO object nor a Tk window.

splitlayout .layout -help
$manager split -help
$manager move -help
$manager constraints -help
$manager constraints $leaf -help

Help is available for creation and all package-defined public instance commands. Inherited TclOO and oo::configurable commands retain their standard interfaces. Standard TclOO new and create also recognize constructor help. Formatting uses argparse’s textutil::adjust dependency from Tcllib.

Quick start

package require splitlayout

wm title . {Split layout example}
wm geometry . 900x600

splitlayout .layout -width 900 -height 600
pack .layout -fill both -expand 1

set root [.layout root]
lassign [.layout split $root -orient horizontal -ratio 0.4 -keep first] left right

set leftFrame [.layout frame $left]
set rightFrame [.layout frame $right]

text $leftFrame.editor -width 20 -height 10 -wrap word
$leftFrame.editor insert end {Content in the left pane.}
pack $leftFrame.editor -fill both -expand 1

text $rightFrame.editor -width 20 -height 10 -wrap word
$rightFrame.editor insert end {Content in the right pane. Drag the sash to resize.}
pack $rightFrame.editor -fill both -expand 1

The splitlayout .layout ... command returns the widget pathname. Use that pathname both as the layout command and with Tk geometry managers. The constructor accepts -width, -height, -opaqueresize, -sashpreview, -draghandles, -buttonside, -showstructure, -dockopts, -structureopts, and -sashpreviewopts.

Splitting existing content

Continue from the quick-start example:

lassign [.layout split $right -orient vertical -ratio 0.65 -keep first] top bottom

set bottomFrame [.layout frame $bottom]
ttk::label $bottomFrame.status -text {New bottom pane}
pack $bottomFrame.status -fill both -expand 1

The original right-hand editor remains in $top, with the same widget pathname and state. $right now identifies the parent split; $top and $bottom are new leaf identifiers. -keep second would retain the editor in the second child instead. Both children are returned in pane order.

Adding panes at the same level

Insert beside a leaf or a split, provided that it has a parent:

set middle [.layout insert $left -side after]
set middleFrame [.layout frame $middle]
ttk::label $middleFrame.label -text {Middle pane}
pack $middleFrame.label -fill both -expand 1

# The root now has three children: left, middle, and the right-hand split.
.layout proportions $root {2 1 3}

Insertion divides the target child’s existing share equally between that child and the new leaf. The -side option accepts before or after, with after as the default. To add panes when the root is still a leaf, split it first.

proportions accepts one finite positive weight per immediate child and normalizes the weights. The example assigns shares of 2/6, 1/6, and 3/6. For a split with exactly two children, ratio queries or sets the first child’s fraction:

.layout ratio $right 0.7
set fraction [.layout ratio $right]
set shares [.layout proportions $root]

Geometry changes settle through Tk’s event loop. Immediately after setting proportions, a query can return the stored values before the sashes have moved.

Minimum content sizes

$manager minsize $leaf 200 120
puts [$manager minsize $leaf]                ;# 200 120 (content area)
puts [$manager requiredsize [$manager root]] ;# Recursive outer minimum
$manager minsize $leaf 0 0                   ;# Clear the content-area minimum

minsize id ?width height? accepts a leaf or an owned floating token. Both dimensions must be supplied together as nonnegative integer pixels; the default is {0 0}. Splits have calculated requirements, not independently assignable minima. Values belong to content: they follow swaps, moves, the child selected by split -keep, and undocking/redocking. A newly created leaf starts at {0 0}. Removing content removes its stored minimum.

requiredsize id accepts a leaf, split, or floating token and returns {width height}. It adds header/button space and leaf borders to the content minimum. For a horizontal split, child widths and themed sash widths are summed and the largest child height is used. Vertical splits use the opposite axes. Each split’s structure border and padding are added when enabled. Removing, inserting, or moving children updates the calculated requirement. The query excludes the manager hull’s padding/border, native window decorations, and application widget requests. It works before mapping; sash dimensions come from the active ttk theme without modifying its styles.

With explicit minima configured, requested proportions are fitted to available space while respecting child requirements. Both live and deferred sash gestures stop at the adjacent panes’ feasible limits. When the parent is too small, child requirements along each split axis are compressed proportionally; requested minima are retained and apply again when space becomes available. A cross-axis shortage likewise cannot satisfy the requested minimum. Very small allocations may leave no visible content after sashes and decoration consume the available pixels. Setting {0 0} clears the content requirement; enabled headers and borders still require space. Layouts that have never been assigned minima retain their existing sash behavior.

Floating windows receive wm minsize based on their content and decoration. Header visibility, image sizes, border settings, and theme changes refresh constraints through the normal idle geometry pass. The manager does not set wm minsize on the application’s owning toplevel: applications can use requiredsize and account for their other widgets if they want to enforce a window minimum. Native window-manager behavior remains platform-dependent. Tk may report a larger minimum than requested because of native window limits. In particular, Windows can report a positive minimum width after setting wm minsize to 0 0, and its reported limits can change when a window is first mapped. requiredsize reports the manager’s calculated requirement, not the native effective window minimum. Constraints cover manager operations and gestures; direct modifications through the exposed native panedwindow command bypass the manager until its next geometry application.

Movement and locked content

-nomove checks only the directly moved leaf. It is not imposed on ancestors. In a swap, both existing flags are checked because both contents would move; no flag is added to the destination. Moving another leaf beside protected content is allowed, including converting its current leaf position into a split. Moving or wrapping an ancestor, changing neighboring panes, and normal geometry changes can change a protected leaf’s screen position.

-nomove alone does not prevent undocking, docking, deletion, splitting, resizing, or moving a floating window on screen. -noundock is the separate restriction on leaving the docked tree. It does not prohibit returning floating content with dock, or moving and swapping it while docked. The current public move, swap, and undock commands accept leaves, not complete split subtrees; movement flags cannot be assigned to split nodes.

-locked true sets both movement flags and protects adjacent placement boundaries. move and dock, including gestures, reject placing content against the edges selected by -lockedside. Shared slots check both neighbors: naming the unlocked neighbor with -before or -after cannot bypass the restriction. Sash and outer-rim drop zones use the same validation. Internal ancestor sashes check only their direct leaf neighbors: locking the bottom leaf of a vertical middle split does not block the outer vertical sashes beside that split. Its own selected edges and adjacent sibling slots remain protected, and a directly neighboring locked leaf can still block an internal slot.

There is one exception: an insertion boundary coinciding with an outer root edge also checks descendants touching that edge. For example, a nested bottom leaf blocking bottom blocks placement below the whole root, or below its containing split when that split reaches the root’s bottom edge. Its left/right settings do not block internal ancestor sashes. Descendants that do not touch the selected root edge do not restrict it. The rule uses the proposed tree after removing a moving source, works before mapping, and applies to commands, gestures, outer-rim drops, and remembered docking alike. It never changes stored flags or side lists.

-lockedside is a list of blocked physical edges: left, right, top, and bottom. The default is {left right top bottom}. For example, leave the right edge available so other floating windows can return even when this is the only remaining docked leaf:

$manager constraints $editor -locked true -lockedside {left top bottom}
$manager dock $floatingToken -right $editor

Both sides of a shared slot are checked against each neighbor’s own physical edge: inserting after a leaf checks its right edge in a horizontal parent and its bottom edge in a vertical parent. The opposite neighbor’s left or top edge is checked too. Before/after are destination commands, not valid lockedside values. Split neighbors are searched for locked descendants only at coincident outer root edges.

An empty list allows incoming placement on every edge while keeping the locked leaf’s movement and undocking restrictions. Setting -lockedside alone does not enable locking; it can be configured in advance, and it is preserved when locking is switched off and on. Queries return a unique list in left/right/top/bottom order. The setting belongs to leaf/floating content, follows retained splits and docking, and cannot be set on a split. Invalid lists reject the whole update without changing settings or cancelling active gestures.

Default docking still tries its remembered destination (or the existing fallback); it does not search for an unblocked edge. If that destination is blocked, use an explicit open edge such as dock -right, or drag to that edge. Buttons and native close requests use the same default-destination validation as before.

Locked is stored explicitly. Setting -nomove true -noundock true separately does not lock destinations. -locked false clears locking and both movement flags without changing other restrictions. Clearing either movement flag individually also clears locking, leaving the other flag unchanged. Set -locked in a separate call from -nomove or -noundock; mixing them in one update remains an error. Existing no-op moves are allowed.

Locking does not block explicit creation through split or insert, deletion, sash resizing, or ordinary geometry changes. Use -nodestroy, -noresize, and subtree limits for those separate restrictions. The flag follows retained content through splitting and docking just like the other leaf flags. A floating locked frame may be docked at an allowed destination; once docked, its adjacent boundaries are protected.

Destruction and collapse

-nodestroy on leaf content rejects remove, clear, and retain when they would delete that content, even through an ancestor. It does not prevent undocking or splitting with retained content, because the frame survives. Removing an unprotected sibling is allowed, including automatic collapse of an unprotected parent that preserves protected content. A split explicitly marked -nodestroy cannot itself be deleted or collapsed; otherwise its unprotected descendants may still be edited or removed while the split survives.

Ancestor flags are not rewritten. An ancestor can report -nodestroy false while a descendant makes its removal illegal. Validation considers everything the whole operation would delete before changing any widgets or records. Delete buttons obey these restrictions. Native close with -onclose destroy leaves protected content open; -onclose dock attempts normal docking and likewise leaves the window open if the destination violates constraints.

These are manager policies, not an access-control boundary. $manager destroy, direct Tcl destroy, destruction of an actual Tk ancestor, and application shutdown remain possible. Removing an outer manager’s content also destroys nested managers inside it; their independent policies cannot veto their actual Tk ancestor’s destruction. Raw Tk commands obtained through frame, widget, or panedwindow can bypass manager policies.

Resize locks

-noresize rejects sash gestures that would change the allocation of a protected node, including ancestor sashes. An explicitly locked split can still adjust its own internal sashes if its children are not locked. With resize locks present, a sash cannot push neighboring sashes to resize a more distant protected pane. Changing constraints cancels active manager gestures and prevents further movement from an already active native live sash gesture.

Changed ratio and proportions settings are conservatively rejected if the configured split contains a locked descendant: minimum-size fitting can redistribute space beyond the requested panes. Reapplying the identical stored proportions is allowed. A lock on the split itself does not prohibit its internal proportion changes. Unrelated subtrees remain resizable.

This does not freeze an absolute size or enforce wm resizable: resizing the application or a floating window, changing minimum sizes or decoration, and structural operations such as split, insert, move, swap, and dock may resize the content. A floating content flag takes effect on its sash allocation after docking. Use minsize for minimum dimensions; the manager must still compress allocations when its parent supplies insufficient space.

Leaf counts and depth

A leaf counts as one and has depth zero. A split containing only leaves has depth one; nesting adds one per edge. Thus -maxdepth 0 prevents splitting that node or converting it into a split by moving or docking another leaf at its edge. Counts include all docked descendant leaves, not only immediate children. Floating content is excluded. Minimum counts are nonnegative integers; maxima accept nonnegative integers or -1. A default layout counts its placeholder as one leaf. A rootless layout has zero leaves and no node constraints. All numeric constraint values are limited to 2147483647.

The complete final layout is checked after planned insertion, source removal, and automatic collapse. Moving within one bounded subtree does not temporarily violate its count. Moving between subtrees must satisfy source and destination limits and all affected ancestors. Undocking can violate a minimum; docking, splitting, and insertion can violate a maximum or depth limit. Reordering flat siblings does not increase depth.

Automatic collapse cannot evade the old parent’s minimum: its surviving replacement subtree is checked against that parent’s limits before collapse is allowed. Limits belong to structural node identity and are discarded when that node expires; they are not transferred to a promoted child. Explicit deletion of an entire constrained subtree (including clear) removes its limits rather than requiring it to remain present. Add -nodestroy to protect the node’s existence. Surviving ancestors’ limits are always checked.

New limits must already be satisfied by the current subtree, and minimum must not exceed a finite maximum. Invalid updates leave all settings and active gestures unchanged; no panes are silently removed or rearranged to fit.

Ownership, commands, and gesture feedback

Leaf flags belong to the content frame and follow allowed swaps, moves, and docking transitions. When a leaf is split, they follow the child selected by -keep; the new empty child has default flags. Split flags and subtree limits belong to node identity. Limits assigned to a leaf stay on that identifier when it becomes a split. Leaf IDs expire on undocking, so their structural limits are discarded; the floating content retains its flags and redocking creates a new node with default limits. Floating queries show default subtree-limit values, but setting those limits requires a docked node. Removing content discards its flags.

Commands reject prohibited operations before allocating widgets, changing IDs, cancelling gestures, or mutating the tree. Errors have -errorcode {SPLITLAYOUT CONSTRAINT option id} and identify the restriction that blocked the action. Identical-node swaps and moves, and already-adjacent moves that make no change, remain no-ops. Drop previews suppress invalid destinations and release does nothing there. Header buttons retain their action icons, including custom images, and become inactive when their current action is illegal. The same image is assigned explicitly to normal and disabled states; ttk still controls button styling. Blocked native close requests leave the window open without a background error. Flags are explicit settings, not a cached summary of every action that might be prohibited by descendants or ancestor bounds.

For example, in the layout built above:

# Insert it before the entire right-hand region in the root split.
.layout move $middle -before $right

Edge destinations reuse the target’s parent when it already has the required orientation. Otherwise, a target leaf becomes a new split containing the source and a new leaf for the target’s existing content. This follows split’s identifier semantics: the target identifier now denotes a split. Use children, leaves, or locate to obtain the new target-content leaf identifier. If the target is already a split, a new parent split is created around the source and target subtree; the target keeps its identifier unless source removal leaves it with a sole child and normal collapse promotes that child. A split target may contain the source, including the root. For example, .layout move $source -right [.layout root] places the source beside the remaining layout in a new horizontal root. The source identifier remains unchanged and is also the command’s return value.

For example, a perpendicular move in a two-pane horizontal layout changes it to a vertical layout:

splitlayout .example
pack .example -fill both -expand 1
lassign [.example split [.example root] -orient horizontal] a b
set moved [.example move $a -top $b]
# moved equals a; b is now the root vertical split.

-before and -after always use the existing parent orientation. They can describe a sash destination without pixel coordinates: insertion at a sash is -before its following child or -after its preceding child. A split target may contain the source; moving beside that ancestor moves the source outside its subtree. Insertion beside the root is an error, except that any move to oneself is a no-op.

Reordering within the same parent preserves the pane weights associated with each node. Other moves divide the target’s share equally between the source and target. Remaining siblings in the source parent retain their relative weights. If only one child remains there, it replaces the old parent after insertion; that old parent identifier becomes invalid. Query root again after a move that can collapse the root.

Moving to oneself or to an already adjacent position with the requested orientation does nothing. Invalid arguments are rejected before modifying the layout. A structural move cancels an active deferred sash gesture, rebuilds geometry once, and lets geometry settle through the normal event loop. No application content is destroyed.

move changes pane placement; swap exchanges content at two existing positions.

Dragging panes

Enable minimal, manager-owned grips for every leaf with the global -draghandles property:

splitlayout .docking -draghandles true -opaqueresize false
pack .docking -fill both -expand 1
lassign [.docking split [.docking root]] first second

# The existing content API is unchanged.
set f [.docking frame $first]
text $f.editor
pack $f.editor -fill both -expand 1

# Hide all grips and reclaim their space, including for leaves created later.
.docking configure -draghandles false

The default is false. When enabled, each leaf has a full-width rectangular header containing an optional centered title, a dock/undock button, and a delete-content button. The grip uses ttk theme colors and a height scaled to Tk’s display scaling. Application widgets remain entirely inside the frame returned by frame; pack and grid configurations there survive toggles and moves.

By default, the outermost 12 pixels inside the megawidget form an outer drop zone (limited to one eighth of its size). This zone takes precedence over sashes and local leaf edges. It allows moving a pane to the far right or left of an entire stacked region, or above/below an entire row. Farther inside, sashes take precedence over leaf edge zones. Local edge zones default to up to 24 pixels into a pane, limited to one quarter of its width or height; corners choose the nearest normalized edge. The preview is blue by default, is temporary, and does not resize or rearrange content during dragging. Release performs one move, swap, undock, or dock; a click without dragging does nothing. The -sashpreview setting controls deferred sash resizing only, not this docking preview.

Escape, loss of grip focus, hiding or resizing panes, moving or hiding the containing window, structural layout changes, or disabling -draghandles cancels the gesture. The grip temporarily takes keyboard focus and a local mouse grab so that release outside the grip and Escape are handled. Cleanup restores the prior focus when still owned by the grip and releases only its own grab. A new gesture does not replace an existing grab. Dragging into separate splitlayout instances or other applications is not supported; an outside drop creates an owned floating window instead.

With handles enabled, widget leaf returns the pane wrapper, whereas frame leaf always returns the application content frame. container leaf resolves the wrapper’s outer geometry container; container $contentFrame resolves the wrapper that packs the content. node recognizes either pathname. locate resolves application widgets and manager-owned grips to their current leaf. Logical tree snapshots expose both widget and frame; actual widgets snapshots also include the wrappers, grip canvases, and any temporary preview frames.

The wrapper and grip stay at their leaf position during a swap; only content frames are exchanged. A move preserves the moved leaf and its wrapper, while normal split/collapse rules may replace destination wrappers. Disabling handles removes wrappers unless leaf borders still need them; do not cache wrapper or grip paths across layout changes. Application content paths remain stable.

Floating windows also have a full-width internal grip when -draghandles is enabled. Drag this grip to move the floating window and preview destinations in its owner layout. Drop on an edge, sash, or outer rim to dock there. A floating drop in a leaf’s center docks to its right (it does not swap or discard that leaf). Its untouched sole-root placeholder is filled instead. Release elsewhere keeps the window floating at its new position. Escape cancels and restores the starting position. Moving native window decorations only moves the window; it does not initiate docking.

Buttons accept keyboard focus and do not start dragging. The global -draghandles property controls both strips, including these buttons. A floating strip spans the window width and reserves space using the content labelframe’s label-widget area, preserving application pack and grid settings. The manager owns the content frame’s label-widget options; applications should configure children inside the content frame. A docked header with both layout movement and undocking blocked inherits its normal parent cursor, has no drag-area tooltip, and does not take a grab on press. Button tooltips remain available. If either operation remains possible, the hover cursor is an open hand; destination constraints still apply to each drop. An accepted mouse press immediately closes the hand. Crossing the drag threshold changes it to a closed hand holding a small window, which remains visible until release or cancellation, including over invalid destinations. Returning the pointer near its starting position does not deactivate the drag. A simple click or small motion below the threshold makes no layout change and shows no placement preview. Header buttons always use the ordinary arrow cursor, including disabled buttons, rather than inheriting the hand cursor. Hand artwork and platform handling are embedded in splitlayout.tcl; no additional asset files need installation. Windows uses embedded monochrome .cur assets; X11 uses embedded XBM source and mask assets; macOS uses native openhand and closedhand cursors, and loads the embedded CUR for active dragging. The custom assets share a 32-by-32 canvas and a fixed hotspot, so changing state does not shift the pointer. They are original package artwork.

Files are created lazily in the system temporary directory, shared across managers in the interpreter, and removed when the last manager using them is destroyed. No files are written into the installation directory. Abrupt process termination may leave temporary files behind. If creation or loading fails, hover, pressed, and active dragging fall back to fleur, exchange, and icon, respectively. No extra package or C extension is required.

Lock button

The lock button shows an open padlock while unlocked and a closed padlock while locked. Custom image keys describe the next action: lock is displayed while unlocked, and unlock while locked. A dynamic tooltip describes the action and current constraints. The button remains available when movement, undocking, or deletion is blocked, so the user can release a lock. Programmatic constraint changes update its image and tooltip. Like the other buttons it supports keyboard activation, never starts a drag, and disappears when -draghandles is false.

The lock tooltip reports layout movement and undocking as locked/unlocked from the explicit -nomove and -noundock flags, and lists the docking sides blocked by locking. It shows none when locking is off or its side list is empty, even if an inactive side list is still stored. For example:

Unlock pane
Layout movement: locked
Undocking: locked
Docking sides blocked by locking: left, top and bottom

These are current local restrictions, not predictions of the next click or a summary of every ancestor limit. An unlocked movement flag does not override other constraints. Direct constraint updates and button clicks refresh the tooltip in docked and floating headers. -tooltips false and missing Tklib disable it exactly like the other header tooltips; no custom fallback is created.

Edges on the immediate parent split’s boundary

For a horizontal split, every child touches top and bottom; the first child also touches left and the last also touches right. For a vertical split, every child touches left and right; the first also touches top and the last also touches bottom. Nested leaves use their own immediate parent split, even where that split’s boundary is internal to the manager. Root leaves and floating content have no parent split and use all sides.

$manager configure -draghandles true -lockbuttonmode outer

Clicking to lock sets -locked true and the computed -lockedside together, replacing any previously stored side selection. Clicking again uses -locked false, clearing both movement flags while retaining the side list. Sides are captured at click time: later insertion, collapse, docking, or mode changes do not recompute them. To recalculate, unlock and lock again. Changing the mode does not change direct constraints semantics, existing flags, or an active drag. The mode belongs to each manager independently, including nested managers.

Leaf outlines

Enable -leafborder true to surround each leaf’s header and content with one independent outline.

The header and content share the same inner left and right edges. Floating windows use the same settings. With leaf outlines enabled, the header draws only its bottom separator; its top and side borders are omitted. -headerborderwidth sets separator thickness and -headerrelief its native bottom-edge relief. Flat or zero thickness hides the separator. Disabling leaf outlines restores the header’s complete rectangle. The outline remains when -draghandles false; -showstructure continues to describe split groups separately. No application widgets are recreated or reparented. Geometry managers reserve the border’s thickness.

$manager configure -leafborder true -leafborderwidth 2 -leafrelief ridge
$manager configure -leafopts {-color #808080}

-leafborder defaults to false, -leafborderwidth to 1, and -leafrelief to solid. Relief accepts flat, solid, raised, sunken, ridge, and groove. Flat or zero width hides the visible line. -leafopts accepts -color, the classic border’s base color (default #909090); raised relief shades derive from that color, while solid relief uses Tk’s solid-border rendering. It does not override ttk styles. Set the option database resource *splitlayoutLeafColor (class SplitlayoutLeafColor) before construction to change the default. Dictionary updates are validated atomically and retain unspecified keys. Changes cancel active gestures and preserve content, titles, and logical split proportions. Floating borders temporarily use the content frame’s background as their base color; the prior background is restored when the border is disabled or the window is docked.

Header appearance and titles

The title and empty header area accept dragging; the action buttons do not. Header colors and title font follow ttk theme defaults. Header relief and thickness are global properties; they do not override ttk button styles:

$manager configure -headerrelief ridge -headerborderwidth 2 -buttonside left
$manager title $leaf "Waveforms"
set heading [$manager title $leaf]
$manager title $leaf "" ;# Remove the heading.

-headerrelief accepts flat (default), raised, sunken, ridge, groove, and solid. -headerborderwidth is a nonnegative integer pixel count (default 1). A zero-width border is invisible. Changing either property cancels an active drag and applies to existing docked and floating headers.

title id ?text? accepts a leaf or floating token. Titles belong to content, so they survive swaps, moves, retained-content splits, docking, and undocking; removing content removes its title. Titles default to empty. They are independent of the native floating title set by undock -title. Display uses one line, replacing line breaks with spaces and shortening long headings with an ellipsis. The getter returns the original text. Centering reserves equal space at both ends for either button alignment, keeping the title clear of buttons.

Title alignment and custom button images

-titlealign left|center|right defaults to center and is independent of -buttonside. Left and right titles use the respective edge of the free header area, with padding. Centered titles remain centered in the whole header. All alignments shorten long text to avoid the buttons; the stored title remains unchanged.

Choosing which header buttons appear

-headerbuttons selects the manager-wide set of visible buttons. The default is {lock dock close}. The dock button toggles docking and undocking. The close button uses -closeaction, which defaults to destroy. Use header to override either setting for one content frame:

$manager configure -headerbuttons {lock dock}
$manager header $leaf -buttons {dock close} -closeaction hide
$manager header $leaf -buttons {}           ;# Title and grip only.
$manager header $leaf -buttons inherit      ;# Use the manager's button selection again.

An omitted button occupies no space and has no tooltip or keyboard focus. Hiding the dock button still permits drag-to-undock or an explicit undock command when constraints allow it. A visible button is disabled whenever its operation is prohibited. For example, -nohide disables a cross configured to hide, while -closeaction none disables the cross regardless of constraints. Use inherit for either per-content option to resume following its manager default. Overrides survive hide/show and undock/dock.

-buttonimages accepts dock, undock, delete, lock, and unlock for pane headers, and tabadd, tabclose, and tabclosedisabled for the notebook. Values are existing Tk image names, not filenames or raw SVG data. PNG and SVG files/data can be loaded into Tk photo images first:

set undockImage [image create photo -file undock.png]
set dockImage [image create photo -file dock.svg -format svg]
$manager configure -titlealign left -buttonimages [dict create undock $undockImage dock $dockImage]
$manager configure -buttonimages {delete {}} ;# Use the built-in delete bitmap.

Overrides apply globally to existing and future docked and floating headers. Partial dictionaries preserve other entries; an empty value restores that action’s built-in bitmap. An empty dictionary changes nothing. Invalid keys or missing image names reject the whole update. The toggle uses undock while docked and dock while floating. The lock button uses lock or unlock according to the current constraint state. Button widths and header height accommodate the images at their native pixel size; images are not scaled or recolored. Supply appropriately sized icons and retain them while used. The manager never deletes supplied images. To delete one, clear/replace its override first. If an image is deleted externally, a subsequent refresh falls back to the built-in bitmap. After changing an image’s dimensions in place, reapply its override to refresh header sizing. Tk photo images hold rasterized SVG output, not editable vector data.

Optional tooltips

-tooltips true|false defaults to true. When enabled, the manager attempts package require tooltip and uses Tklib tooltip for the drag area and action buttons. Drag-area text describes rearranging/undocking or moving/docking, depending on whether the content is docked or floating. If the package cannot load, there are no tooltips and no custom fallback. Set -tooltips false to remove this manager’s tooltip registrations. It does not disable application tooltips globally or change their delay, font, colors, or fading. Setting it to true retries loading the optional package. The value returned by configure -tooltips is the requested preference, even when the package is unavailable.

Nested managers

A leaf can contain another splitlayout instance as ordinary application content:

set content [$outer frame $hostLeaf]
set inner [splitlayout $content.inner -draghandles true -opaqueresize false]
pack $inner -fill both -expand 1
lassign [$inner split [$inner root]] first second

Each instance owns its tree, gesture state, previews, and floating tokens. Starting a drag on an inner header rearranges only the inner layout. Starting on the containing outer header moves the complete inner manager with its content frame. An outer drop over the inner layout targets the containing outer leaf. An inner drop outside the inner hull undocks that inner leaf, even if the pointer is still inside the outer manager. Individual leaves cannot be transferred between managers; docking accepts only the originating manager’s floating tokens. An active grab prevents another manager from starting a competing content drag.

Undocking or redocking a containing leaf updates the actual owner toplevel of all nested managers, including hidden instances. Stale gestures are cancelled, owner event bindings move to the new toplevel, and subsequent deferred sash previews use that window as their transient owner. Independently floating descendants keep their own toplevel ownership. Mapping and gesture entry also refresh ownership after external Tk promotion. Removing the containing content destroys its nested managers and their owned floating windows.

Minimum sizes are independent between instances. The outer manager does not infer constraints from embedded application widgets. To constrain the host leaf, set its content minimum from the inner root’s requiredsize, adding any hull padding or other surrounding widgets, and refresh it when the inner requirements change.

Swapping and removing content

The following operations continue the example above:

# Exchange complete content frames across different nesting levels.
.layout swap $left $bottom

# Remove the middle pane and all widgets it contains.
set survivingParent [.layout remove $middle]

# Keep top, destroy its sibling subtree, and replace their parent with top.
.layout retain $top

swap exchanges content frames; node identifiers continue to identify the same logical positions. Cached frame and application-widget pathnames remain valid, but may now belong to a different leaf.

remove destroys the requested subtree. If its parent has only one child left, that child replaces the parent. retain destroys all siblings of the retained node and collapses its immediate parent; it does not collapse all ancestors. Retaining the root does nothing.

To discard all content and start again:

set root [.layout clear]

Previously removed node identifiers are invalid. Use the return values or query the layout again after structural changes. To destroy the entire layout, use .layout destroy or destroy .layout.

Visual structure

Enable outlines for the whole layout to distinguish flat sibling arrangements from nested groups:

.layout configure -showstructure true
# Also accepted at construction:
splitlayout .outlined -draghandles true -showstructure true

By default, each split receives a one-pixel gray outline and two pixels of inner spacing, giving a three-pixel inset on each side. Customize these dimensions and colors with -structureopts or the option database described below. Flat siblings share one enclosing outline; a nested split has an additional inset outline around its children. A sole root leaf has no split outline. The setting is independent of drag handles and applies to future splits. During docking, the receiving group outline turns blue alongside the existing destination preview. For a local edge move that creates a new split, the highlighted outline is the current enclosing group. Escape, an invalid destination, and release restore the normal outline color.

Changing -showstructure cancels active gestures and rebuilds geometry while retaining content, native panedwindows, and split proportions (subject to available pixel space). Disabling it removes the outlines and their spacing. Very small panes can still collapse under Tk’s normal geometry constraints.

With this option enabled, widget split returns the enclosing outline frame. Use panedwindow split to obtain the native ttk panedwindow regardless of the option value, for example:

set split [.layout root]
set pw [.layout panedwindow $split]
set position [$pw sashpos 0]

node recognizes both paths. container split returns the outer geometry container, while container $pw returns the outline frame that packs the native panedwindow. tree includes both widget and panedwindow for splits; widgets exposes the actual geometry containers. Outline frames remain immediate Tk children of the hull.

Floating managed content

undock promotes an existing leaf’s content frame to a native window, removes its leaf from the docked tree, and collapses a parent with only one remaining child. The application widgets, paths, bindings, and content state are retained. dock returns that owned content to a new leaf. Arbitrary windows and other managers’ floating content are not accepted. For mouse-driven docking and undocking, see Dragging panes.

set content [$manager frame $leaf]
set floating [$manager undock $leaf -title "Waveform" -geometry 600x400+100+100]

# The content frame is now itself the native toplevel.
wm title $content "Floating waveform"
set info [$manager floating $floating]
set allFloating [$manager floating]

# Return it beside an existing leaf or split; the original leaf ID has expired.
set newLeaf [$manager dock $floating -right $target]

The docking destinations are -left, -right, -top, -bottom, -before, and -after, with the same placement rules as move. Specify at most one. Edge destinations accept leaves or splits; sibling destinations require a non-root target. Docking reuses a matching parent orientation, converts a leaf target into a split when necessary, or wraps a split target in a new parent. Existing pane shares are divided equally at the insertion point.

Use hide leaf to release the pane’s space while retaining its content frame and widgets. The returned frame pathname doubles as its hidden token. Use hidden to list these frames and show frame to restore one at its remembered position. Hidden content is outside the logical tree. Hiding and showing respect subtree limits. A refused show can be retried. Use remove frame to discard hidden content.

Use header leaf -closeaction hide to make its header cross hide the content, destroy (the default) to delete it, or none to disable the button. The setting follows the content. The separate -nohide flag blocks hiding from either the header or the command. A pane protected only by -nodestroy can be hidden. Floating headers follow the same rules; the native window close button follows -onclose.

With no destination, dock tries the sibling positions saved by undock, nearest first, with the original orientation and relative order (following siblings take precedence at equal distance). The first surviving sibling node is used, including if it has become a split. Node identity represents a position: swapping its content does not invalidate it. If it has moved, docking follows that node at its current location. Deleted anchors are skipped. Returning to the original split restores the floating pane’s share at undock time. The remaining panes divide the rest according to their current proportions. If the split collapsed, docking restores the saved division beside the promoted sibling. Minimum sizes may limit the resulting sash positions. Explicit destinations, relocated anchors in other splits, and fallback positions use ordinary insertion sizing. If no anchor remains, dock places the content to the right of the current root. Undocking the sole root of a layout that allows zero leaves makes it rootless. Implicit docking then makes the returning pane its root. An ordinary layout creates an empty placeholder leaf. An implicit dock replaces that placeholder if it is still the root, has no header title, and its content frame has no child widgets. If you populate it, both contents are retained. Explicit destinations always follow the requested placement instead of replacing the placeholder.

undock accepts -title (default splitlayout), -geometry (default current content size and position), and -onclose dock|destroy (default dock). The native close button therefore returns content to the current layout by default, trying its remembered position before using the fallback destination. Use -onclose destroy to discard the content on close, or $manager remove $floating to destroy it explicitly. $manager clear and removing the docked root clear only the docked tree; floating windows remain owned by the manager. Destroying the manager or an actual Tk ancestor destroys all owned floating windows as well. Direct destruction of a floating frame removes its record.

Floating tokens are opaque, manager-specific handles. They expire on docking or removal, and must not be reused. floating lists these tokens; floating $token returns a dictionary with id, frame, title, geometry, state, and onclose. frame $token returns the retained frame. Docked-tree commands (tree, leaves, node, and locate) exclude floating content; widgets still exposes its actual Tk ancestry and wm geometry manager.

Content frames are classic ``labelframe`` widgets with class ``Frame``, borderless while docked, because Tk’s wm manage cannot promote ttk::frame. The hull, panedwindows, and header buttons retain their ttk behavior; leaf wrappers use classic frames for configurable borders. Code using frame $leaf for pack, grid, or child creation continues to work; ttk-only frame options such as -style are no longer available on that content frame. Place themed widgets inside it when needed. Actual parentage remains the layout hull throughout the round trip.

Tk default bindtags follow the changed toplevel. The manager also retargets explicit bindtag entries naming the old toplevel, restoring unchanged custom lists on docking and preserving other edits made while floating. Binding scripts containing literal window paths are not rewritten. Applications that cache winfo toplevel should query it again after a docking transition. Preserve manager-owned bindtags if changing a floating frame’s bindtags directly.

Window promotion uses Tk’s wm manage/wm forget, so native activation, positioning, and decorations depend on the platform/window manager. Invalid destinations are rejected before unmanaging the floating window. Failure to promote or apply the requested geometry restores the docked layout. Windows and Aqua behavior should be verified on their native Tk builds; X11 test results alone do not establish macOS compatibility.

Notebook workspaces

The first addtab title puts the existing tree in a notebook page. By default each further call creates a root leaf. tabs lists stable page pathnames, selecttab ?page? queries or selects a page, and root ?page? returns the selected or specified root. For example:

set transient [.layout addtab Transient]
set ac [.layout addtab AC]
.layout move $plot -right [.layout root $ac]

Commands accepting node IDs can operate across pages. With no node argument, tree, leaves and clear apply to the selected page. Hidden and floating content remembers its home page for implicit restoration, even if a different tab is selected. Ordinary pages receive a fresh root leaf when their last pane leaves. Once the notebook exists, adding a page or its first leaf preserves the mapping of existing panes. Tree edits rebuild the affected pages. For example, splitting a pane on a background tab or deleting that tab keeps panes on the selected tab mapped. Docking a floating pane into another tab updates the destination tree and both tabs’ close buttons.

Starting without a root

-empty allows the layout to have zero leaves. With splitlayout .layout -empty, the hull exists immediately. Before the first leaf is added, root, leaves, tree and clear return the empty string. Use addleaf to create the first content frame. Once a root exists, use split or insert to add panes.

::splitlayout::splitlayout .layout -empty
set plot [.layout addleaf]
set main [.layout addtab Main]
set comparison [.layout addtab Comparison -empty]
.layout move $plot -tab $comparison
# Main now has zero leaves. Comparison's root is the original plot.

The first tab inherits the layout. It adopts the current tree, including pane IDs and content frames, and inherits the constructor’s permission to have zero leaves. You may also opt in when creating the first tab with addtab Main -empty on an ordinary manager. A populated tree is adopted intact. An unused default root leaf is discarded so a fresh manager can still create its first tab empty.

Later tabs choose independently. addtab title creates one root leaf and replaces the last departing pane with a placeholder. addtab title -empty starts with zero leaves. Moving, hiding, undocking or removing its last pane leaves the page empty and selectable. An empty page is a single drop target. move $leaf -tab $page and dock $floating -tab $page place the incoming pane at its root. addleaf $page creates a fresh leaf there without changing the selected tab.

Reordering tabs

Use movetab $page -before $other or movetab $page -after $other to reorder the tab strip. The selected page, pane IDs, and split proportions survive the move. To reorder with the mouse, press a tab label and drag to either half of another label. The insertion line shows where release will place the tab. Escape or release outside a label cancels. A click selects the tab.

Hold a dragged header over a tab label briefly to open that page. Drop inside it using the ordinary centre, edge, outer rim and sash destinations. Hovering alone never commits a change. Releasing over a label leaves both trees intact; Escape restores the starting page. The usual movement, boundary and subtree constraints apply to both trees before a drop commits.

Adding tabs with the + button

The + button follows the last notebook tab. Clicking it selects a new empty page with the first available title in the sequence Tab 1, Tab 2, and so on. A rootless layout also shows +, including after deletion of the last tab. A populated plain layout enters notebook mode with addtab.

Set -tabaddbutton false to hide the button. Set -tabaddcommand to a Tcl command prefix to replace the whole action. The prefix runs in the global namespace with the layout pathname appended. It controls creation, naming and selection. An empty prefix restores the built-in action. For example, to start editing a custom page title immediately:

proc addPlotTab {layout} {
    set page [$layout addtab "New plot" -empty]
    $layout selecttab $page
    $layout edittab $page
}
$layout configure -tabaddcommand addPlotTab

Use -buttonimages to set the notebook artwork independently of the pane header buttons:

$layout configure -buttonimages [dict create tabadd $plusImage tabclose $closeImage]
$layout configure -buttonimages [dict create tabclosedisabled $disabledCloseImage]
$layout configure -buttonimages {tabadd {} tabclose {} tabclosedisabled {}}

Each empty value restores that symbol’s built-in image. Protected tabs use the disabled symbol. Hover mode reserves the dimensions of the corresponding close image. Choose an add image that fits the tab strip height (or its width for a vertical strip). The application owns the supplied images.

Renaming a tab

Double-click the tab title to edit it in place. Return or a click elsewhere commits the text. Escape cancels. Use edittab $page to open the same editor from application code. Set -tabrename false to disable interactive editing and discard an open edit. The application can always set a title with renametab $page $title. Changing the title preserves the page pathname and its content.

Deleting a tab

deletetab $page destroys its docked tree and every hidden or individually floating pane whose remembered home is that page. A pane already moved or redocked into another page belongs to that page. All affected content frames and split nodes are checked for -nodestroy before deletion. If any are protected, the command raises a constraint error and the entire tab survives.

By default, hovering over a tab reveals a close cross at the trailing edge of its label. Press and release on the same cross to delete that page, including when another page is selected. Releasing elsewhere or pressing Escape cancels. Drag the label text to reorder. Once the drag crosses the threshold, the cursor changes to the same hand holding a window used for pane drags. A protected tab remains selectable and shows a disabled cross. The cross uses deletetab and its destruction constraints; the pane header’s -closeaction applies only to individual panes.

Set -tabclosebutton to hover (default), always, or none at construction or with configure. Hover reserves the same space as always so labels stay still. None removes that space. Deleting the last tab leaves a plain, rootless manager. Use addleaf to populate it directly, or addtab title to start a new notebook.

Inspecting the layout

Use logical node identifiers when working with the layout structure, and widget pathnames when working with Tk:

set leaf [lindex [.layout leaves] 0]
set contentFrame [.layout frame $leaf]

set logicalParent [.layout parent $leaf]
set geometryContainer [.layout container $leaf]
set actualParent [winfo parent $contentFrame]

set layoutTree [.layout tree]
set widgetTree [.layout widgets]

For a non-root node identifier, container returns its parent panedwindow. Its actual Tk parent remains .layout. With handles enabled, passing the content frame pathname instead returns its pane wrapper. winfo manager reports the manager name, not the pathname of that geometry container.

node maps an exact managed frame or panedwindow pathname to its node identifier. locate accepts a descendant application widget and walks its Tk parents to find the containing leaf:

set leaf [.layout node $contentFrame]
# For any existing application widget inside a content frame:
set applicationWidget [lindex [winfo children $contentFrame] 0]
if {$applicationWidget ne {}} {
    set leaf [.layout locate $applicationWidget]
}

tree returns nested dictionaries containing id, type, parent, widget, and children. Leaves also contain frame. Splits contain panedwindow, orient, and proportions, plus ratio when they have two children. Split children are nested node dictionaries in pane order.

Floating content is described separately by floating; widgets still includes its actual Tk subtree.

Both snapshots are for inspection. They do not serialize application widget state or provide a restore operation.

split

Replaces a leaf with a split containing two new leaves.

SPLITLAYOUTOBJ split node ?-orient orientation? ?-ratio fraction? ?-keep child?

Parameters

-keep child:

Child receiving the existing content: first or second; default first.

-orient orientation:

Split orientation: horizontal or vertical; default horizontal.

-ratio fraction:

First child fraction, strictly between zero and one; default 0.5.

node:

Identifier of the existing leaf to split.

Description

The original leaf identifier becomes the split identifier, and both child leaves receive new identifiers. The retained content frame and its widget descendants are reused without reparenting or recreation. The other child starts with an empty frame. Existing pane proportions are captured before rebuilding the layout.

Return value

The two new leaf identifiers in pane order.

swap

Exchanges the content frames assigned to two leaves.

SPLITLAYOUTOBJ swap a b

Parameters

a:

First leaf identifier.

b:

Second leaf identifier.

Description

The leaves can belong to different splits and nesting levels. Their logical positions remain unchanged, while complete content frames and their existing widget state move between those positions. Actual Tk parentage and widget pathnames remain unchanged. Equal identifiers do nothing.

Return value

Nothing.

title

Gets or sets the optional header title belonging to managed content.

Parameters

id:

Docked leaf identifier or owned floating token.

text:

Optional title; an empty string removes the heading.

Description

Titles follow content through swaps, moves, splitting with retained content, and floating transitions. They do not change the native window title set by undock -title. Rendering uses one line and truncates long headings to keep the buttons unobscured; the stored string is returned unchanged.

Return value

The current title string.

tree

Returns a recursive snapshot of the logical layout hierarchy. A nested dictionary describing the requested logical subtree, or empty for a rootless page.

SPLITLAYOUTOBJ tree ?id?

Parameters

id:

Subtree root identifier; empty selects the layout root.

Description

Each node dictionary contains id, type, parent, widget, and children. With handles enabled, widget is the wrapper for a leaf. Leaf dictionaries also contain the application content frame as frame, with an empty children list. Split dictionaries contain orient and proportions; two-child splits also contain ratio. With showstructure, widget is the enclosing split wrapper. The panedwindow field always names the native split widget. Split children are nested node dictionaries in pane order.

Proportions are refreshed from usable geometry unless application is pending.

Return value

Returns a recursive snapshot of the logical layout hierarchy. A nested dictionary describing the requested logical subtree, or empty for a rootless page.

undock

Removes a leaf from the layout and promotes its retained content to a floating window.

SPLITLAYOUTOBJ undock leaf ?-title title? ?-geometry geometry? ?-onclose action?

Parameters

-geometry geometry:

Optional Tk window geometry; defaults to the current content size and screen position.

-onclose action:

Window close action: dock or destroy; default dock.

-title title:

Window title; default splitlayout.

leaf:

Existing docked leaf identifier.

Description

Content widgets and their pathnames survive. The former leaf identifier expires and single-child parents collapse. Undocking the sole root leaves either zero leaves or the ordinary placeholder. The floating frame keeps its actual parent, so destroying the hull also destroys its floating windows.

Return value

An opaque floating token, accepted by dock, floating, frame, and remove.
